# PlugPark v0.8.0-R1 운영 릴리스 계획

이 문서는 R1-5에서 계획만 고정한다. 이 단계에서는 Cloudflare remote D1, 실제 부산/EV API, Worker deploy를 실행하지 않는다.

## R1-6 목표

운영 데이터에 typed charger availability(available_fast_count, available_slow_count)를 안전하게 초기화한 뒤 v0.8.0-R1 Worker를 한 번만 배포하고 최소 smoke와 실제 UI QA를 수행한다.

## 배포 순서

1. 최소 remote preflight 1회
   - 현재 production health/read-model 상태와 migration 적용 여부만 확인한다.
   - 대형 ev_chargers COUNT/scan을 preflight에서 반복하지 않는다.
   - preflight 실패/불명확 시 중단한다. 자동 retry 금지.

2. migration 0006 정확히 1회
   - ev_stations.available_fast_count / available_slow_count
   - ev_station_live_status.available_fast_count / available_slow_count
   - 성공 여부가 불명확하면 재실행하지 않고 migration state부터 확인한다.

3. 기존 D1 데이터 기반 typed read-model 초기화
   - 공공 API 전체 재수집 금지.
   - 기존 ev_chargers + ev_status를 사용해 R1 FAST/SLOW 분류식과 동일한 집계를 한 번 수행한다.
   - ev_stations와 ev_station_live_status의 새 컬럼을 모두 초기화한다.
   - 기본값 0을 실제 값으로 오인한 상태에서 public smoke를 하지 않는다.
   - R1-6에서 one-shot SQL/스크립트로 만들고 로컬 dry-run 후 remote 1회만 실행한다.

4. R1 Worker deploy 정확히 1회
   - 자동 deploy retry 금지.
   - deploy 결과가 불명확하면 deployment 목록/버전부터 확인한다.

5. EV incremental status sync 1회
   - 배포 후 현재 충전 상태를 갱신하기 위한 최소 live sync만 수행한다.
   - full EV info backfill은 하지 않는다.
   - 호출량/실패 상태를 확인하고 자동 retry하지 않는다.

6. 최소 production smoke
   - /api/health
   - /api/places 1회
   - runtimeMode = live
   - upstreamEvCalls = 0
   - upstreamParkingCalls = 0
   - typed availability 불변조건 확인
   - public /api/places가 raw ev_chargers를 직접 scan하지 않는 구조 유지.

7. 실데이터 UI QA
   - 추천: 주차/충전 우선
   - 충전: 상관없음/급속/완속
   - fresh/stale 문구
   - 주차 만차 제외
   - 지도 포커스/상세/길찾기
   - PC/모바일
   - LIVE DATA 표시 확인

## 실패 처리

- migration, typed init, deploy, live sync 중 하나라도 실패하거나 결과가 불명확하면 즉시 중단한다.
- 같은 명령을 자동 재시도하지 않는다.
- 먼저 현재 remote 상태를 읽고, 이미 적용/배포되었는지 확인한 뒤 다음 수동 조치를 결정한다.
- 실패를 숨기기 위해 full backfill이나 반복 deploy를 실행하지 않는다.

## R1-6에서 금지

- 개발 중 반복 remote probe
- full EV info 재수집
- /api/places에서 ev_chargers/parking_lots 직접 full scan
- migration/deploy 자동 retry
- 실제 typed 초기화 전에 정상 가용 수라고 단정
